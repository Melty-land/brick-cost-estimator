# 用料明细(含剩余材料)+ Excel 导入导出模板 —— 设计规格

- 日期:2026-10-02
- 项目:浙江陆创新材料科技有限公司「砖成本材料预算 · 成本估算系统」
- 状态:待用户复核
- 硬约束:**零第三方依赖、完全离线**(无 npm/CDN/外部字体;Excel 解析与生成均为自研,仅用浏览器内置 API 与 Node 内置模块)

## 一、背景与目标

系统已具备:材料档案、产品配方、估算单(Excel 化预算表)、成本总览、图表预览、历史对比、数据备份/导入恢复。
本期新增三件事:

1. **用料明细** —— 新增页签,按产品编号自动匹配,提供**逐批逐料的可查看明细**(每行末尾带该材料该批次的**期末结存**),并提供**剩余材料表**;汇总口径(按砖型统计、材料总消耗)沿用现有「成本总览」,不重复建设。
2. **Excel 导入** —— 上传 Excel,按表头自动匹配字段(可人工修正映射),校验后批量导入**估算单/预算表**。
3. **导出 Excel 模板** —— 导出与导入字段一一对应的模板,用户填写后可直接导入系统。

> 章节按**使用流程**排列:功能 1(用料明细)→ 功能 3(导出模板)→ 功能 2(导入);章节号与功能编号保持对应,便于交叉引用。

成功标准:用户能在明细页逐批逐料核对用料与结存(某产品某批用了哪些料、用了多少、这批用完还剩多少);能下载模板→填写→导入,无需手工逐格录入;导入过程可预览、可纠错,不产生半截数据。

## 二、范围

**做**:扁平模板导出(.xls)、三格式解析(.xlsx / .xls / .csv)、字段映射预览与校验、估算单批量导入、用料明细页(用料明细表 + 剩余材料表,含筛选与导出)。

**不做**(本期明确排除):
- **产品汇总表、材料总消耗汇总**(与现有「成本总览」的按砖型统计/材料总消耗重复),明细页不再重复展示;
- 导入材料档案、产品配方(仅导入估算单;材料需已存在于材料档案,否则该行报错);
- 预算表 12 列网格版式的解析(留作后续增量,本期模板为扁平表);
- 导出 .xlsx(本系统只生成 SpreadsheetML 2003 `.xls`;导入侧支持 .xlsx);
- 多用户并发导入、导入历史回滚(仍依赖既有数据快照/备份机制)。

## 三、功能 1:用料明细与剩余材料

### 3.1 入口与位置
- 新增页签「**用料明细**」,顺序:`材料管理 | 产品配方 | 估算单 | 成本总览 | 用料明细 | 图表预览 | 历史对比 | 用户管理`。
- hash 路由:`#usage`;深链可直接打开。

### 3.2 筛选条件(页面顶部)
- **时间段**:开始日期 ~ 结束日期(按估算单 `startDate` 过滤;留空=不限);
- **产品**:多选(默认"全部");数据来源为产品档案的产品名/编号;
- **材料**:多选(默认"全部")。
- 筛选只影响展示与汇总,不修改任何数据。
- 默认统计范围:**全部估算单**(含草稿与可用)。

### 3.3 产品自动匹配规则
对每张估算单依次尝试,首个命中即采用:
1. `estimate.productId` 命中产品档案 → 该产品;
2. 「名称规格」(`estimate.name`)与产品名完全相同 → 该产品;
3. 「预算表编号」(`estimate.code`)与产品编号(`product.code`)完全相同 → 该产品;
4. 均未命中 → 归入「**未匹配产品**」分组(编号显示原 `code`,名称显示「未匹配产品」),并在页面顶部提示"有 N 张估算单未匹配到产品,请检查名称规格或产品编号"。

同名/同编号命中多个产品时,取产品档案中**最先出现**的一个,并在提示中列出。

### 3.4 表格 A:用料明细(逐批逐料)
一行 = 一个批次 × 一种材料(**本页核心表格**):

| 列 | 口径 |
|---|---|
| 预算表编号 | 估算单 `code` |
| 批次日期 | 估算单 `startDate` |
| 产品编号 / 产品名称 | 按 3.3 匹配结果 |
| 材料名称 | 材料行 `name` |
| 所属区 | 材料行 `zone`(底料/面料) |
| 每锅数量(公斤) | 材料行 `qtyPerPot` |
| 锅数 | 该材料所属区的锅数(底料=`potBottom`,面料=`potTop`) |
| 本期用料(公斤) | `qtyPerPot × 对应锅数` |
| 单价(元/公斤) | 材料行 `price` |
| 金额(元) | 本期用料 × 单价 |
| 占比 | 该行用料 ÷ 该批次「本期用料数量合计」 |
| **期末结存(公斤)** | 该行材料的 `上存材料 + 本期进料 − 本期用料`;**负数标红** |

- 排序:批次日期降序 → 产品编号 → 用料降序;
- 材料筛选生效时,占比仍按**该批次全材料合计**为分母(与原表口径一致);
- 顶部显示小计:「共 N 张预算表 / M 行明细 / 合计用料 X 公斤 / 合计金额 ¥Y」(仅作行数规模提示,不与成本总览的汇总重复)。

### 3.5 表格 B:剩余材料
一行一种材料(受材料筛选影响),跨筛选范围累计:

| 列 | 口径 |
|---|---|
| 材料名称 / 所属区 | 材料档案 |
| 累计上存(公斤) | Σ 各批次该材料「上存材料」 |
| 累计进料(公斤) | Σ 各批次该材料「本期进料」 |
| 累计用料(公斤) | Σ 各批次该材料「本期用料数量」 |
| **累计剩余(公斤)** | 累计上存 + 累计进料 − 累计用料;**负数标红**并显示为负值 |
| **最新批次结存(公斤)** | 该材料在**批次日期最新**的命中批次中的「库存材料」(`上存+进料−用料`);若最新批次无该材料则不显示该行值(显示「—」) |
| 涉及批次数 | 含该材料的命中批次数量 |

排序:累计剩余升序(最缺的在前)。当材料筛选生效时,仅保留筛选材料。

### 3.6 空数据与边界
- 无任何估算单:两张表显示空提示,不报错;
- 某批次无材料行:跳过该批次(不计入明细);
- 未匹配产品的行照常出现在明细中(产品编号显示估算单 `code`、产品名称显示「未匹配产品」),不受影响;
- 期末结存 / 累计剩余为负时标红显示(含义:用料超出上存+进料)。

### 3.7 导出
两张表各自提供「导出 Excel」按钮,复用现有 `Exporter.buildSpreadsheetML` 生成 `.xls`(工作表名分别为「用料明细」「剩余材料」),导出内容 = 当前筛选后的表格数据。

## 四、功能 3:导出导入模板

### 4.1 入口
估算单列表页工具栏新增按钮「**下载导入模板**」(与「导入 Excel」相邻)。

### 4.2 文件格式与结构
- 格式:`SpreadsheetML 2003` 单文件 `.xls`(Excel 可直接打开编辑并另存);
- 工作表 1「**估算单导入**」:
  - 第 1 行:表头(中文列名,含单位,见表 4.3);
  - 第 2 行:示例行(1 行,内容为标注「示例」的说明性数据,导入时按 5.5 规则自动忽略);
  - 第 3 行起:用户填写区。
- 工作表 2「**填写说明**」:逐字段说明(含义、单位、是否必填、格式示例)+ 三条填写规则:
  1. 一行 = 一个批次的一种材料;同一「预算表编号」的多行合并为一张预算表;
  2. 同一预算表编号的批次公共字段(名称规格/日期/砖规格/锅数等)各行保持一致;
  3. 材料名称必须是材料档案中已存在的名称。

### 4.3 模板字段(扁平表列)
| 分组 | 列名 | 系统字段 | 必填 |
|---|---|---|---|
| 批次 | 预算表编号 | `code` | 是 |
| 批次 | 名称规格 | `name` | 是 |
| 批次 | 开始日期 | `startDate` | 是 |
| 批次 | 结束日期 | `endDate` | 是 |
| 批次 | 编制人 | `author` | 是 |
| 砖规格 | 砖长(mm) | `calc.length` | 是 |
| 砖规格 | 砖宽(mm) | `calc.width` | 是 |
| 砖规格 | 砖高(mm) | `calc.height` | 是 |
| 砖规格 | 每块重量(公斤) | `calc.perPieceWeight` | 是 |
| 砖规格 | 每模块数 | `calc.perModuleCount` | 是 |
| 砖规格 | 每托块数(块) | `calc.perPalletCount` | 是 |
| 砖规格 | 每托平方(m²) | `calc.perPalletSqm` | 是 |
| 批次 | 底料锅数 | `potBottom` | 二者至少填一个(>0) |
| 批次 | 面料锅数 | `potTop` | 同上 |
| 材料 | 材料名称 | `rows[].name` | 是 |
| 材料 | 每锅数量(公斤) | `rows[].qtyPerPot` | 是 |
| 材料 | 单价(元/公斤) | `rows[].price` | 是 |
| 材料 | 上存材料(公斤) | `rows[].stockOnHand` | 否(空=0) |
| 材料 | 本期进料(公斤) | `rows[].stockIn` | 否(空=0) |

- 材料「所属区」**不设列**:由材料档案的所属区决定(避免用户填错导致配比区不一致);若用户需要指定,后续增量再加。
- 导入后估算单的其余派生值(面积/体积/每平方重量/吨价/成本总价等)由系统按既有公式引擎自动计算,模板不需要也不接受这些列(出现则忽略)。

## 五、功能 2:Excel 导入

### 5.1 入口
估算单列表页工具栏「**导入 Excel**」→ 打开导入视图(整页视图,非弹窗,便于展示映射与预览)。

### 5.2 支持格式与解析
| 扩展名 | 解析方式 |
|---|---|
| `.csv` | 自研 CSV 解析:支持双引号包裹、`""` 转义、CRLF/LF、UTF-8 BOM 去除;取第一张表 |
| `.xls` | 自研轻量 XML 解析(见 5.3.1)读取 SpreadsheetML:`ss:Worksheet`(多表时由用户选择)、`ss:Row`、`ss:Cell`(支持 `ss:Index` 跳列)、`ss:Data` |
| `.xlsx` | 自研 zip 读取 + 同一 XML 解析器(见 5.3) |

解析结果统一为:{ sheets: [{ name, rows: string[][] }] },单元格一律转为字符串(数字保留原始文本,日期见 5.5)。

**5.3.1 统一 XML 解析器(浏览器/Node 通用,零依赖)**
- 不使用 `DOMParser`(Node 无此 API,单测无法运行),改为自研**标签扫描式**解析器:支持元素嵌套、属性(单/双引号)、自闭合标签、文本与 CDATA、XML 实体(`&amp; &lt; &gt; &quot; &apos;` 及数字实体)、忽略注释与 XML 声明;命名空间前缀按字面比较(如 `ss:`/`x:` 前缀在解析时剥离,按本地名匹配);
- 该解析器同时服务 `.xls`(SpreadsheetML)与 `.xlsx`(OOXML)两条路径,可在 Node 中直接单测。

### 5.3 .xlsx 解析要点(零依赖)
1. **读取 zip**:定位 End of Central Directory → 中央目录条目 → 本地文件头 → 取压缩数据;
2. **解压**:`compressionMethod=0`(stored)直接取;`=8`(deflate)用浏览器 `DecompressionStream('deflate-raw')` 解压;若环境不支持(Node 测试)则用 `zlib.inflateRawSync`(Node 端注入);
3. **取内容**(均用 5.3.1 的统一 XML 解析器):`xl/workbook.xml`(工作表名与顺序)、`xl/_rels/workbook.xml.rels`(表名 → 文件路径)、`xl/sharedStrings.xml`(共享字符串)、`xl/worksheets/sheetN.xml`;
4. **单元格取值**:`t="s"` → 查 sharedStrings;`t="inlineStr"` → `<is><t>`;`t="str"` → `<v>` 文本;无 `t` → `<v>` 数值文本;`<v>` 缺失且无 `<is>` → 空;
5. **范围**:忽略样式、公式计算结果取 `<v>`(缺失则空)、忽略合并单元格(扁平模板不需要)。
- 解析器为纯函数、可在 Node 中单测(Node 侧传入 `inflateRaw` 实现)。

### 5.4 字段智能识别与手动映射
- **别名表**(不区分大小写、忽略空格/全角括号/单位后缀;命中即映射):
  - 预算表编号:`预算表编号 / 编号 / 批号 / 批次号 / code`
  - 名称规格:`名称规格 / 产品名称 / 砖型 / 规格 / name`
  - 开始日期:`开始日期 / 起始日期 / 开工日期 / startDate`
  - 结束日期:`结束日期 / 完工日期 / 截止日期 / endDate`
  - 编制人:`编制人 / 填报人 / 制表人 / 负责人 / author`
  - 砖长:`砖长(mm) / 长 / 长度 / length`;砖宽:`砖宽(mm) / 宽 / 宽度 / width`;砖高:`砖高(mm) / 高 / 高度 / height`
  - 每块重量:`每块重量(公斤) / 每块重量 / 单重 / 单块重量 / perPieceWeight`
  - 每模块数:`每模块数 / 模块数 / perModuleCount`;每托块数:`每托块数(块) / 托块数 / perPalletCount`;每托平方:`每托平方(m²) / 托平方 / perPalletSqm`
  - 底料锅数:`底料锅数 / 底锅数 / 底料`;面料锅数:`面料锅数 / 面锅数 / 面料`
  - 材料名称:`材料名称 / 材料 / 品名 / 原材料 / material`;每锅数量:`每锅数量(公斤) / 每锅数量 / 每锅用量 / qtyPerPot`;单价:`单价(元/公斤) / 单价 / price`;上存:`上存材料(公斤) / 上存 / 期初库存`;进料:`本期进料(公斤) / 进料 / 本期入库`
- 识别顺序:① 列名与系统字段名完全一致 → ② 去单位/空格后与别名表匹配 → ③ 模糊包含匹配(别名是列名子串)→ 未命中则列为「未映射」;
- **预览界面**:每个系统字段一行,右侧下拉选择对应表格列(默认=自动识别结果),可手工改;消耗掉的列自动排除,避免重复映射;「材料名称」「每锅数量」「单价」三个材料级字段必须映射,否则不可导入。

### 5.5 校验规则(预览中逐行标出)
1. 示例行忽略:仅当该行**不含有效的「预算表编号」**(即该单元格为空或含「示例」二字)时才跳过;正常数据行不受影响;
2. 必填缺失:表 4.3 中标"是"的字段为空 → 错误;
3. 锅数:底料锅数、面料锅数至少一个 > 0 → 否则错误;
4. 数值格式:砖长/宽/高、每块重量、每模块数、每托块数、每托平方、每锅数量、单价、上存、进料须为数字(允许千分位逗号);上存/进料可空(按 0 处理);
5. 日期格式:接受 `YYYY-MM-DD`、`YYYY/M/D`、`YYYY.M.D`、Excel 日期序列号(1~2958465,按 1900 基准转换)、`YYYY年M月D日`;无法解析 → 错误;
6. 材料存在性:材料名称须在材料档案中存在(按去空格后的名称精确匹配);不存在 → 错误,提示"材料『X』不存在,请先在材料管理中创建";
7. 同一预算表编号的分组一致性:名称规格/日期/砖规格/锅数等公共字段各行不一致 → 警告(取首行,并在预览中标出异常行);
8. 材料重复:同一预算表编号内同一材料出现多次 → 错误(避免重复计料)。

### 5.6 预览界面结构
- 顶部:文件名、工作表选择(多表时)、共解析 N 行;
- 左/上:字段映射区(系统字段 → 列下拉);
- 右/中:数据预览(前 50 行,错误行底色标红、警告行黄色,悬浮显示原因);
- 底部汇总:「将导入 X 张预算表 / 共 Y 行材料;错误 Z 行」;**存在错误行时不可导入**(需先修正文件或取消映射);
- 冲突区(见 5.7):列出同预算表编号已存在的条目与处理方式下拉。

### 5.7 冲突处理
- 判定:导入分组中的「预算表编号」与现有估算单 `code` 完全相同(去空格、区分大小写) → 冲突;
- 默认处理:**跳过**(不导入该张),预览中明确标出「已存在,跳过」;
- 可逐条改为「覆盖更新」(更新该估算单的公共字段与材料行,保留其 id)或「新建副本」(生成新估算单:名称规格追加「(导入副本)」,预算表编号追加 `-副本`;若该编号仍冲突则继续追加 `-副本2`、`-副本3`…直到唯一);
- 若"跳过"导致 0 张可导入 → 提示并不执行。

### 5.8 落库
- 分组 → 估算单草稿对象(与编辑器新建同构):`name/code/startDate/endDate/author/potBottom/potTop/calc.*/rows[]`;
- 材料行:`{ id, materialId, name, zone(取材料档案), qtyPerPot, price, stockOnHand, stockIn, qty: '' }`;
- 派生字段由 `Sheet.evaluate` 回写(与编辑器"保存"一致),保证导入后成本①/②、吨价、每平方价等与手工录入完全一致;
- 状态:只要**无错误行**(警告不阻断,按 5.5.7 取首行值)即可导入,导入结果一律 `ready`(必填字段已由校验保证齐全);
- 写入:`Store.addEstimate(draft)`(自动分配 id 与 seq)+ `Store.save()`,成功后提示「已导入 X 张预算表」并跳回估算单列表;失败则整体不写入并提示原因。

### 5.9 错误处理
- 非 Excel/CSV 文件、文件过大(>8MB)、zip 损坏、无工作表、表头行缺失 → 顶部提示原因,停在导入视图;
- `.xlsx` 解压不可用(浏览器不支持 `DecompressionStream`)→ 提示"请另存为 .xls 或 .csv 后重试";
- 写入失败(网络/权限)→ 提示"导入失败:原因",不修改本地数据。

## 六、架构与组件

## 九、术语与口径确认

| 术语 | 含义 |
|---|---|
| 本期用料数量 | 每锅数量 × 对应区锅数(公斤) |
| 库存材料 | 上存材料 + 本期进料 − 本期用料数量(可为负) |
| 累计剩余 | 筛选范围内 Σ(上存+进料−用料) |
| 最新批次结存 | 批次日期最新的那次估算单中的库存材料 |
| 未匹配产品 | 估算单未能按 3.3 规则关联到任何产品档案 |
| 期末结存 | 单条明细行对应材料在该批次的 `上存 + 进料 − 本期用料`(即该批次该材料的库存材料) |

## 十、实现顺序(供实现计划拆分)

本规格覆盖一个特性群,建议拆成**两个实现计划**,按依赖顺序:

1. **阶段一 · 用料明细**(功能 1):`stats.js` 聚合 + `#usage` 视图(用料明细表含期末结存 + 剩余材料表)+ 筛选 + 两表导出 + 单测(stats/CDP)。独立可用,不依赖 Excel 能力。
2. **阶段二 · Excel 模板与导入**(功能 2、3):`xlsio.js`(统一 XML 解析器 → 三格式解析 → 别名识别 → 校验 → 模板生成)+ `Exporter` 多表扩展 + 导入视图 + 列表页两个按钮 + 单测(xlsio/端到端 CDP)。

阶段二依赖阶段一:导入完成后需在用料明细页核对数值,因此先做阶段一。
